# ADAM — Claude Code guide

ADAM ("Amiga Dev and Art Machine") is a no-code Amiga game maker written in
GameMaker (GML), by Bob / Polytricity Ltd. It is modelled on Bob's C64 No-Code
tool (github.com/RobertRamsay/C64_NOCODE) and is a separate product from the
older AMIGA_DEV_MACHINE_Git node editor.

Users paint a backdrop, draw sprites, place actors, write WHEN/DO rules, make
sounds and levels, then ADAM writes a **bootable .ADF** for a stock
**Amiga 500/600 (OCS/ECS, 1MB chip, FS-UAE model A600)** or **Amiga 1200
(AGA, 2MB chip)**, picked at launch.

## Golden rules (Bob's conventions — always follow)

- **Initialise every instance variable in `obj_app` Create** (arrays, structs, flags). Never rely on `variable_struct_exists` / `variable_instance_exists` checks. For data read from JSON, use `struct[$ "key"]` and `is_undefined` / `is_array` / `is_string`.
- **No ternary / shorthand if** (`a ? b : c`). Always full `if { } else { }`.
- **Never write hex as `$ff` at the start of an array literal** — `[$ff...]` parses as a struct accessor. Use `0xff` everywhere.
- **Never name a local `x` or `y`** (built-in instance variables). Use `_px`, `_iy`, etc.
- Brace style: Allman, 4-space indent, `_underscore` locals, as in the existing scripts.
- Bob reviews changes as diffs/patches. Keep changes focused, one feature per commit, with a clear message. If you hand him something to paste instead, use **FIND:** / **REPLACE with:** blocks.
- `#macro ADAM_DEV_TOOLS true` (scr_adf) enables the FS-UAE test-copy download. It must be `false` for public itch.io builds.

## How to build and check

- **Compile GameMaker from the command line** with Igor (GameMaker's build CLI) so compile errors can be read and fixed. Locate the installed runtime (usually under `%ProgramData%\GameMakerStudio2\Cache\runtimes\runtime-*\bin\igor\windows\x64\Igor.exe`) and run a Windows VM build of `ADAM.yyp`. Iterate until there are **zero errors**; also clear Feather errors where possible.
- **Engine:** `powershell -File tools\assemble_engine.ps1` (needs vasmm68k_mot.exe).
- **Engine test without GameMaker:** `python tools\reference\gen_examples.py` then `powershell -File tools\run_adf.ps1 -Adf tools\reference\out\gem_hunter.adf` (or `-Model A1200`).
- `gen_examples.py` is deterministic: running it must not change `datafiles/examples/*.adam` unless the examples were meant to change.
- Bob does the hands-on UI checks in the running app; describe exactly what to click to verify each change.

## Architecture

### Editor (GameMaker)
One object, `obj_app`, draws everything in **Draw GUI** with an immediate-mode UI
(`scr_ui_widgets`, `scr_ui_draw`, `scr_ui_help`). Every control registers a rect
(`ui_register`) for hover help and tutorials. Pages ("workspaces", `WS_*` in
`scr_ws_shell`): Home, Backdrop, Levels, Sprites, Animate, Tiles, UI, Actors, Logic, Sound, Music, Build.

| Script | Role |
|---|---|
| `scr_project` | Data model (`project_new`, `project_from_loaded` = loader + validator), per-page undo (`undo_keys`, `undo_mark`, `undo_mark_full`), settings ini. |
| `scr_machine` | Machine profiles (`machine_cur()`), launch picker, boing ball. |
| `scr_gfx` | Backdrop index surface + `sh_palette` shader (palette & copper-sky preview), sprite caches, font, PNG import (median cut). Painting writes `bd_buf` then uploads — never draws into the surface. |
| `scr_levels` | Levels page, terrain generator (`terrain_generate`, LCG — must match `gen_examples.py`), title/goal settings. |
| `scr_adf` | **Game data block + ADF writer**, FS-UAE launch/test-copy download. |
| `scr_sfx` | Synth + WAV sample import, crunch (rate/bits), preview (exact Paula output). |
| `scr_patch` | Patch sounds (sound `kind` 2, settings in `sfx.patch`, `global.PATCH_DEF` / `PATCH_PRESETS`): 3 oscillators (sync / ring / FM / unison), SVF filter + envelope, amp / pitch envelopes, 2 LFOs, 3 mod slots, chorus / drive / crush / echo, one-shot or looped sustain. `patch_render` makes one sample at the Paula rate of the tracker note with the patch note's pitch class (`patch_root`), so it is in tune as an effect and an instrument. GML only (not in `adf_reference.py`); the disk format is unchanged. |
| `scr_ws_*` | One script per page. `scr_ws_logic` also owns rule groups. |
| `scr_examples`, `scr_tutorial` | Example loader, tutorials. (There is no in-app intro; the YouTube intro is rendered by `tools/intro`.) |

Project data (`proj`) is plain JSON-able structs/arrays; `.adam` files are `json_stringify(proj)`.

### Runtime (68000)
`datafiles/engine/engine.s` is a **fixed, position-independent** engine
(`vasm -pic`). ADAM never generates code: it appends a **data block** right
after `engine.bin`; `boot.s` (bootblock) AllocMem's chip RAM, reads engine+data
with trackdisk (showing a copper loading bar) and jumps in.
ADAM Pro loading screen (`scr_loadscr`, `proj.loadscr`, `loadscr.s`): the disk is `[boot][loading-screen block][engine][data]`; the bootblock's last 16 bytes are `screenload, screenmem, loadsize, bsssize` (0, 0 = the plain bar). The block is `loadscr.bin` + `LS_*` header (48 bytes, version 2: `LS_MODE` fills 0 left to right / 1 right to left / 2 bottom to top / 3 top to bottom; `LS_NPIC` / `LS_PICS` pictures at a percentage, `PI_*` 16 bytes: threshold 0..1024, byte column, line, bytes across, lines, data = the screen bytes with it drawn in, shown in order) + ADAM's copper list (with the game's copper sky when it shows the backdrop) (BPLxPT / SPRxPT values are offsets from the block, fixed up by init) + picture planes + a strip of the full bar; entries 0 init / 4 progress (d0.w 0..1024) / 8 done; it is freed before the engine starts and falls back to the plain bar without the memory. Editor: the UI page's Loading screen tab (`ui_page_tab` 1, `loadscr_page_draw`; Pro only) - the backdrop or its own PNG (`picture_quantize`, 1-5 planes, A1200 up to 8), Fills (`ls_mode`), pictures at a percentage (`proj.loadscr.pics` { spr, x, y, pct }, up to `LS_PIC_MAX` 16 sprites from the bank in the picture's nearest colours, `loadscr_pics`, dragged on the preview), bar place / size (steppers or drag on the preview), a HUD frame style or Custom pieces drawn in the picture's colours (or a PNG strip, `loadscr_import_strip`), and a progress slider / Play preview (`loadscr_preview_update`, RGB surfaces, no shader). In adf_reference.py: `ls_new`, `loadscr_block`, `adf(..., ls)`; Dig Deep (Pro) has a stone bar and its cast turning up at 20 / 45 / 70 / 90 %, Lesson 7.
Registers held:
`a4` = data block, `a5` = V+128 (variables; per-actor state is a 64-byte record per actor,
`v_xx(a5,Dn)` with Dn = actor << ACTV_SHIFT, up to MAX_ACT = 32 actors), `a6` = $dff000.

**Data block header** (offsets from data start; longs are offsets from data start, 0 = absent):
`0 'ADAM' | 4 version | 6 flags (bit0 AGA) | 8 depth | 10 nact | 12 nrule | 14 lives | 16 show score | 18 show lives | 20 hud row | 22 hud colour | 24 msg colour | 26 player actor (-1) | 28 game block | 32 palette | 36 planes (original) | 40 actors | 44 rules | 48 sfx table | 52 game-over text | 56 win text | 60 sprite pair colours | 64 display planes | 68 copper sky (256 x $0RGB; AGA: + 256 words of low nibbles, written with LOCT) | 72 painted ground (320 words) | 76 work planes (backdrop + hills) | 80 music table | 84 second display (BOBs) | 88 BOB background | 92 tile world | 96 custom HUD | 100 scroll block | 104 named palettes | 108 disk 2 | 112 items` — header is 116 bytes, version 15 (15 = animated tiles, `T_ANIM` in the tile world block; 14 = BOB frame headers; neither added a header field). Music table (`M_*`, see docs/MUSIC_CONTRACT.md): nsongs word, 10 level-song bytes ($FF none), then { offset, length } of each ProTracker MOD.

- BOBs (ADAM Pro): actors with `A_BOB` set are drawn by the blitter into a double-buffered display (`bob_draw` / `bob_flip`), wiped from the background buffer each frame; their images are the sprite's size (16-64 wide in steps of 16, 16-64 high; `A_BSIZE` = BLTSIZE), a mask then depth planes, in the nearest backdrop colours. A sprite bigger than 16 x 24 is always a BOB. Lite puts 8 actors on the disk, Pro up to 32 (actors after the 8th sprite become BOBs). Each BOB frame starts with a 16-byte `BI_*` header (data version 14): first drawn row, rows, first drawn word, words, rightmost pixel, planes empty / solid under the mask; `bob_draw` and its wipe blit only that part (Starfire on the A1200: worst frames ~450 -> 306-350 lines; the A600 still drops frames there).
- Animations (version 5): `A_ANIM` (actor record offset 48) points at a table of 4 x 72 bytes (`AN_*`): Idle, Walk, Jump, Fall - each { frames 1..8, rate, mode 0 loop / 1 once / 2 ping-pong, 0, 8 longs facing right, 8 longs facing left }. ADAM fills empty animations in from the others (`anim_plan` in scr_project = `anim_plan` in adf_reference.py), and writes the two-frame animation of older projects as a table too. `place_sprites` picks the animation (Jump / Fall only for roles 6-8 in the air) and the frame from `v_anim - v_astart`; the frame offset goes in `v_fofs` (bob_draw draws BOBs from it). `A_SPR2` is now only a hopper's crouch frame. With 8 directions (`anim_dirs`, `A_AMODE` bit 0) the table has 12 entries (4..11 = N NE E SE S SW W NW, picked from the move each frame via `dir_tab`, last one in `v_dir`); ADAM bakes turning round into those entries (`flip` in the plan, `DIR_CHAINS` / `anim_dir_chains`), and an empty Idle is written as mode 3 = stand facing the last direction. Fire animations (`A_AMODE` bit 1, 21 entries: 12 Fire, 13..20 Fire + N..NW) play while the player holds fire, picked from the joystick direction; the Animate page shows them on a 'With Fire' layer.
- Hit / Die (`A_AMODE` bit 2; editor slots `ANIM_HIT` 21 / `ANIM_DIE` 22, `ANIM_COUNT` 23, `ANIM_FIRE_END` 21): when either has frames the plan gets two more entries after the 4 / 12 / 21 others (empty Hit plays Die or Idle, empty Die plays Hit; `anim_plan_k` maps a slot to its plan index). DO 26 'Play an animation' (value 0 Hit / 1 Die) sets `v_aplay`; `place_sprites` plays it once and holds the last frame, then `anim_ended` sets `v_aplay` -1, the actor's bit in `v_aended` and `v_aendk`; WHEN 16 'An animation ends' (actor a, n 0 Hit / 1 Die / 2 either). Animate page: Hit / Die tabs under Walk / In air / Falling. Dig Deep: the sword makes a slime safe and plays its Die (squashed flat), WHEN Die ends sends it home. `hide_sprites` now clears all 16 + 16 frame longs.
- Tile world (version 6, `H_TILES`, `scr_tiles` / Tiles page `WS_TILES`): one tile size per game (`proj.tile_size` 8 / 16 / 32 / 64, `tile_geometry()`), up to 512 tile types (`TILE_MAX`; ADAM Lite 96) - `T_*` header 44 bytes (size, shift, line, ncol, nrow, ring), `TP_*` records 8 bytes (byte flags: bit0 solid, bit1 dig, bit2 goal; byte sound; words hard, points, becomes), 4-letter names; map up to 1024 x 1024 tiles (Lite 256 x 256) and never over 32640 pixels (`WORLD_PX_MAX`, engine words), cells are bytes or - with more than 256 tile types (`T_FLAGS` bit 1) - words. The engine copies the map to BSS (cleared memory after the data; the bootblock allocates `loadsize + bsssize`, both poked into the last 8 bytes of boot.bin). The scrolling picture is a ring of `NROW x S x LINE` bytes per plane, kept twice (so the display never wraps): map pixel (x, y) lives at `(y x LINE + x / 8 + 2) mod RING` and RING bytes on (`draw_cell`, `cam_window`, `cop_scroll`: BPLCON1 fine scroll, DDFSTRT $30, AGA FMODE 0), under a copper HUD split at line 8 with modulo LINE - 42. Its size does not depend on the map. Actor coordinates are world pixels; actors collide with solid tiles (`box_solid`, `tile_hres` - steps up tiles up to 16 high - `tile_vres`, `tile_phys`). Dig and place (player only): fire + direction digs, fire alone places the carried tile, up jumps; the HUD shows the carried tile and count. Tile worlds use 7 actors, all hardware sprites (no BOBs): DDFSTRT $30 (fine scroll) steals sprite 7's DMA, so pair 3 holds one actor (`ACT_MAX_TILE`, allocator caps). The editor draws the map through a view cache (`tile_view_surface`) snapped to tiles; the atlas holds 32 tiles a row. Example: Dig Deep (`ex_dig_deep.py`, 16 x 16, Pro extra). Multi-disk games (Bob, Oct 2026): part 1 (level music on disk 2) is done - see Disk 2 below; per-level maps / backdrops on disk 2 are next.
- Animated tiles (version 15, ADAM Pro only - `pro_gate("Animated tiles")`, `lite_trim` makes them still; docs/ISO_LAYERS_PLAN.md step 1): a tile's `anim` = 2..8 tile numbers whose pictures it shows in turn (`anim_rate` 50ths, `anim_mode` 0 loop / 1 ping-pong); the map and physics keep the tile type. `T_ANIM` (tile block offset 44, `T_PROPS` moved to 48) -> `TA_*`: count, `TA_PICS` (NT words: tile -> picture, written 0..NT-1, the engine writes into it), then `TR_*` records of 28 bytes (tile, rate, mode, frames, 8 pictures, runtime count / step / dir). `draw_cell` draws `TA_PICS[tile]`; `tile_anim` (main loop, after `cam_window`) steps each one, marks changed tiles with `TP_FLAGS` bit 5 and redraws their cells in view a few rows a frame (`v_tarow`, `TANIM_DRAW`); `tanim_reset` at level start. Up to `TILE_ANIM_MAX` 32. Writers: `tile_anims_on_disk` (scr_tiles) = `tile_anims` (adf_reference). Editor: the tile panel's Animation box (Pictures adds the tile after the last frame, speed, Loop / Ping-pong, live preview, `tile_anim_pic`). Shoot 'em up maps do not animate them (Build warning). Dig Deep: water (4 frames) and torches.
- Actor record = 68 bytes (`A_*` equates; version 9 added `A_PAT` 52, `A_ENTER` 54, `A_HP` 56, `A_RANK` 58; version 10 `A_TYPE` 60, `A_FIRE` 62, `A_FRATE` 64, `A_FPAT` 66; `A_XMAX` / `A_YMAX` = 320 - width / 256 - height are its screen limits), rule record = 16 bytes (`R_*`), sfx entry = 8 bytes (offset, length in words, Paula period), one per project sound (1..`SFX_MAX` = 64, Lite plays `LITE_SOUNDS` = 8; folders `proj.sound_groups`, `sfx.group`), only sounds a rule or dug tile plays get sample data (`sfx_used_on_disk`, the rest length 0); engine masks the sound number with 63, game block = `G_*` (levels, terrain colours, goal, title text, 320 heights per level).
- **Any layout change must be made in three places: `engine.s`, `scr_adf.gml`, `tools/reference/adf_reference.py`.**
- Roles: 0 player, 1 bouncer, 2 patrol L-R, 3 patrol U-D, 4 chaser, 5 still, 6 platform player, 7 hopper, 8 faller, 9 shot, 10 flyer, 11 option, 12 effect.
- WHEN: 0 touch, 1 fire, 2 every N s, 3 score reaches, 4 lives out, 5 game starts, 6 actor jumps, 7 level starts, 8 fire held with the stick still for N tenths of a second (once per hold), 9 every N s while actor a is on the screen (`on_screen`; out of view it fires a second after coming back), 10 the player's weapon strikes actor b (`v_struck`), 11 thrown or shot actor a hits actor b (b = a: anything; `v_hits`), 12 the player picks actor a up (`v_picked`), 13 N seconds into the level (once, `v_ltime`), 14 fire held: at once, then every N frames (auto-fire), 15 the shoot 'em up map reaches its top (once, `v_mend`), 16 actor a's Hit / Die animation ends, 17 the player gets item n (`v_igotp`, a frame late), 18 the player uses item n (space bar menu, `v_useit`) while touching actor b.
- DO: 0 score, 1 lose life, 2 sound, 3 flash the player (it blinks 16 frames via `v_hitf`; the screen never flashes - since 1.1.0, which shipped with a mid red screen flash), 4 home, 5 random spot, 6 hide, 7 show, 8 background colour, 9 game over, 10 win, 11 faster, 12 slower, 13 add life, 14 move to actor, 15 show for a moment, 16 safe for a while, 17 count toward goal, 18 play music (value = song), 19 stop music, 20 place tile (tile world: value = tile, at the target actor's middle / feet / head, only where nothing solid is), 21 drop what the player carries, 22 shoot (target = the shot, value = the shooter), 23 power up (value 0 firepower, 1 speed, 2 add option, 3 lose all), 24 set off effect (target = the effect, value = the actor it goes off at), 25 spawn (a copy of the target that is not out yet comes out at actor value), 26 play an animation (target, value 0 Hit / 1 Die), 27 switch palette, 28 give the player an item (target = how many, value = item), 29 take an item away (same), 30 make a recipe (value), 31 drop an item (value); DO 23 value 4 = homing missiles. `do_target_is_actor` is false from 27 on, `do_value_is_item` for 28 / 29 / 31.
- Items (version 13, Logic page Items tab, `scr_ws_logic` `item_new` / `recipe_new` / `items_fix`; `proj.items` up to `ITEM_MAX` 16, `proj.recipes` up to `RECIPE_MAX` 16): an item has a name (8 letters), the actor picked up as it (touching any copy, `item_tick`; -1 = only rules give it), use 0 used up / 1 kept / 2 a few uses, carry up to, start with, kept on the next level, lost with a life. Disk `H_ITEMS` 112: IT_N, IT_NR, items of 20 bytes (`IT_*`: actor, use byte, flags byte, uses, carry, start, name in 10 bytes), recipes of 8 (`RC_*`: a, b, out, flags keep a / keep b, n). Engine `v_icnt` / `v_iuse` (uses left on the one in use), `item_give` / `item_take` / `item_spend` / `recipe_make` / `item_drop` (a hidden copy comes out `DROP_GAP` beside the player, safe a moment), `items_reset` (game start), `items_level` (`level_next`), `items_life` (`act_loselife`). IF lines (`rule.ifs`, `if_new`, up to `RULE_IFS_MAX` 3, editor '+ IF'): on the disk after the AND DO lines, counted in R_NAND, act = `IF_LINE` ($8000) + cond (0 has / 1 uses - needs one, then `item_spend` / 2 has none / 3 has at least n), target = n, value = item; `fire_action` runs `if_check` first and returns Z set when an IF says no, so `.edge` / score / lives latch only when the rule really fired (a touch rule waiting on a key fires once the key is got). The space bar menu (`tool_menu`, `menu_build`, `menu_take`) now opens in any game with items: tools, then items carried ('< USE KEY 2 >', WHEN 18), then recipes the player can make ('< MAKE TORCH >'); with tools only it looks as before. HUD field type 7 'Item count' (F_DIGITS high byte = item; no label = the item's name). Writers: `adf_if_lines`, the items block before disk 2 (scr_adf) = adf_reference `items` / `recipes` / rule `ifs`, `ui_ref.field_bytes` item. Example: Torchlight (`ex_torch.py`, Pro extra) - KEY opens the cave door (IF uses / IF has no -> sent home), STICK + CLOTH make a TORCH (space bar), the torch used on the bracket (WHEN 18) fades the Dark palette out (the cave's colours 7 / 15 black) and shows the flame, crown and bat; a 2-row Wood HUD with the four item counts. Lesson 8 'Pro - Items: The locked door' (`les_rule_if`). gen_examples: `merge_rules` keys on the IF lines too, `dress_ui` fields take an 8th item, `to_builder` writes `items` / `recipes` with disk actors.
- AND DO: a rule card has up to `RULE_DOS_MAX` (5) DO lines (`rule.more` = `do_new()` structs; `rule_has_act` checks them all). On the disk a rule is 16 bytes with `R_NAND` (word 14) = its AND DO lines, each 8 bytes after it (act, target, value, 0; `AND_SIZE`). `fire_action` runs the DO then each AND DO line (a3 pointed 8 bytes before the line so `do_action` reads it), so every DO on a card fires together even when an earlier one changes what the WHEN looks at (e.g. send home, then safe / sound). `rule_next` steps past a rule and its lines (run_rules, run_when_rules, strike_mask). Up to `RULES_DISK_MAX` = engine `RULES_MAX` = 128 rules (one latch each). `merge_rules` in gen_examples.py merges back-to-back same-WHEN rules of the examples into cards.
- Pick up and throw: actor setting `carry` (`A_CARRY`, the old A_ARATE word). `carry_tick` (before move_actors): fire newly pressed while touching a carriable actor picks it up (`v_carry`), fire again throws it (`v_thr` 1, `v_tvx` THROW_VX the way the player faces, vy -THROW_VY, `physics` does gravity, tile walls and landing); each press is used up (`v_fwait`, checked on the button itself). `carry_follow` (after move_actors) stands it on the player's head. A flying actor's first hit (`throw_hits`, `overlap_pair`, not the player) goes in `v_hits` and it is spent (v_thr 2, drops). Teleports (`stop_fall`) end flights and carrying. The weapon does not swing while carrying. Dig Deep: a Rock (bat colours) to throw at baddies.
- Shooting: role 9 = Shot (`ROLE_SHOT`), hidden at level start. DO 22 `act_shoot` fires the target shot from actor `value`: if it is flying, the next role-9 actors after it are tried (rapid fire); it starts centred on the shooter, `v_thr` = `SHOT_FLY` (3), `v_tvx` / `v_tvy` = speed x direction (diagonals x 3/4), `v_owner` = shooter, `v_pool` = the shot the rule names. The aim is actor setting `aim` written in `A_UP` (0 the way the shooter goes - the player's joystick, else `v_mdx` / `v_mdy`, the last movement kept in place_sprites; a platform player its facing - 1 up, 2 down, 3 left, 4 right, 5 at the player in 8 directions). `move_actors` `.shot` flies it straight and hides it at the screen edge (tile world: in a solid tile or out of view); `shot_hits` (`touch_pair`: shown, not safe; never the owner or another shot) puts (`v_pool`, actor hit) in `v_hits` for WHEN 11 and hides it. Star Catcher: Laser + Laser 2 (aim up), the UFO's Bomb (aim at the player, WHEN 9), shot enemies drop the hidden Star (a faller) with DO 14 + show.
- `V` lies more than 32 KB into engine.bin: reach it from `a5` (= V+128), or `lea start(pc)` + `add.l`, never `lea V(pc)`.
- Custom HUD (version 7, ADAM Pro UI page `scr_ws_ui`, `WS_UI`; `H_UI`, `UI_*` / `F_*`): a panel strip of 1-6 text rows at the top or bottom (always the top in a tile world: `v_hudlines` = rows x 8 is the copper split), its picture = the backdrop strip with a 24 x 24 9-slice frame baked in (`ui_panel_pixels` = `ui_ref.panel_pixels`; blitted into the work planes after the hills, `ui_panel_blit`), a font (64 x 8 bytes; styles ADAM / Bold / Thin / Italic / Bold italic / Custom - `ui_font_bytes` = `ui_ref.font_bytes`; `v_font` is used for all text, so messages and titles match) and up to 16 fields of 32 bytes (type 0 text, 1 score, 2 lives, 3 goal, 4 tile carried, 5 level; column, row, colour, shadow colour or -1, digits, 20-byte label). `draw_char` draws the shadow one pixel down-right inside the cell (`v_shadow`) and clips at column 40. Frame presets (`ui_frame_rgb` = `ui_ref.frame_rgb`): Metal, Wood, Stone, Neon, Parchment, Window, in the nearest backdrop colours. Lite builds use the standard HUD (`lite_trim`). Dressed examples: Firefly Night (wood, italic), Dig Deep (stone, bold).
- Shoot 'em ups (version 9, `H_SCROLL`, `SC_*`; `ex_shmup.py`: Nebula Strike side-scroller, Starfire vertical, both Pro extras): `proj.scroll_dir` 0 none / 1 up / 2 right / 3 down / 4 left (the way the player flies), `scroll_speed` in quarter pixels a frame, `hills_on` (Levels page). The 320 x 256 backdrop is kept twice in buffers in BSS after the data (up / down: 640 lines x 40 bytes, `SCR_PLV`; across: 384 lines x 96 bytes, `SCR_PLH`, BPLCON1 fine scroll, DDFSTRT $30 so 7 sprites, like a tile world), 64 margin lines / pixels so BOBs can be partly off screen; with BOBs 3 buffers (two shown in turn + the background), no disp2 / back. The HUD is always the top strip (copper split, `scroll_show` writes the pointers; `build_grad` `.split` writes them too so a flash never shows garbage). Flyers (role 10, `fly_*`): pattern 0 straight, 1 wave, 2 zigzag, 3 homing, 4 moves with the scenery (turrets), 5 comes in to its place and patrols (boss); `A_ENTER` low byte = edge, high byte bit 0 = comes back; start = placed position a screen beyond the edge (formations keep their shape); hidden flyers wait. `A_HP` = hits before WHEN 11 fires (white flash `v_hitf` on the others); shots stop only at actors a WHEN 11 rule names (`hit_masks`, `v_hitmask`). Options (role 11) follow the player's trail (`v_trail`, `OPT_GAP` x `A_RANK`) and fire one straight shot when the player shoots; effects (role 12) play Idle once and drift with the scenery. Power-ups (`v_power` 0..3 volleys `vol_tab`, `v_pspd`, `v_nopt`) carry over between levels (`power_apply`) and reset on restart. Editor: Actors page (flight pattern, edge, comes back, toughness), Logic page (WHEN 13 / 14, DO 23 / 24), Levels page (scrolling, hills); `scroll_across` / `scroll_on_disk` in scr_ws_actors.
- Shoot 'em up maps (version 10, `SC_MAP` = scroll block word 12, `MP_*` 24 bytes: rows, tile types, images, cells, spawners, flags, `MP_COLS`; `ex_aztec.py`: Jade Serpent, Pro extra): the Tiles page's world dropdown 'A shoot 'em up map' - tiles of 16, `map_w` = the play area's width, an even 12..20 tiles (`SHMUP_COLS_MIN/MAX`, a new map 12: less to draw, so an A500 keeps up), centred on the screen (`shmup_xoff`, engine `v_xoff` / `v_pw`; actor x is across the play area, `world_w()`), the view climbs it once (`map_tick` / `map_line`: each new line drawn once, copied to both ring copies and every buffer). Scroll buffers are `map_w` x 2 bytes a line (`v_sbpr`); the HUD stays full width (`cop_ddf` restores DDF $38 / $d0 at the top, the split narrows it). Spawners (`SP_*` 16 bytes, `proj.spawners`, Spawn tool; `adf_spawner_records` = `spawner_records`) send out waves of an actor's copies; stamps (`proj.stamps`, Stamp tool) are saved metatiles. Copies (`actor.copies`, `disk_expand` = `disk_project`): one actor written N times, `A_TYPE` = the first; rules, spawners and Shoot name the type. Enemies fire by themselves (`A_FIRE` shot, `A_FRATE`, `A_FPAT`, `foe_fire`); aim 6 = homing missile (`missile_steer`). WHEN 15 the map reaches its top, DO 25 spawn a copy at an actor. `shmup_set_cols` keeps the map centred when the width changes. `end_screen` saves `a0` before `scroll_off` (which uses it).
- Engine speed (A600, 50 fps = 312 lines a frame from `wait_vbl` at line 300; a 7 MHz 68000 does about 35 instructions a line): `v_arec` holds each actor's record (no multiply in `actor_rec`); `shot_hits` / `missile_steer` walk only the hit-mask bits with the box test inline; `touch_types` does its box test inline; `run_rules` dispatches WHENs through a jump table; `move_actors` skips hidden shots / flyers / effects with nothing counting down; `place_sprites` counts animation steps per actor (`v_ael`, `v_arem`, `v_astep`, `v_afr`; no divides); `bob_draw` sets BLTPRI while it feeds the blitter (the CPU only waits) with inline waits. A blitter list run by a level-3 interrupt was tried and is slower on a 68000 (each interrupt costs about a line while the blitter waits). Timing: `dbg5.py`-style wrappers in a scratch copy of engine.s that put each routine's raster lines in the score.
- Tile flag bit 3 = ladder: a platform player on it climbs with up / down (no gravity) and lines up with the tile column (`on_ladder`, `snap_col`; digging straight up / down lines up too).
- Tools (Tiles page, Tools tab, `proj.tools`, `TOOL_MAX` 6): `T_NTOOL` (header word 38) tools of 12 bytes (`TL_*`: act word 0 dig / 1 build with the tile carried / 2 put tile `TL_TILE` where the player stands via `ptile_core`, 3 weapon - `TL_TILE` = reach in pixels, flags byte bit 0 = Auto; 8-letter name) after the tile names. Space (`read_key` polls the CIA-A serial port each frame, handshake on `$bfee01` bit 6; `v_key` = $100 + raw code) opens `tool_menu` in the HUD row (`menu_draw` / `menu_clear`, game frozen); left / right pick, fire or space take it (`v_fwait` swallows that fire). Fire then uses `v_tool` (`tile_dig` / `tool_rec`); pickaxe with fire alone digs the way the player faces. No tools = the old fire behaviour. HUD field type 6 = tool name. Weapons (`weapon_tick`, `strike_test`, `strike_mask`): fire swings (`v_swing` SWING_TIME, `v_swcool` SWING_COOL, Fire anim entry 12 facing `v_face`, which holds during a swing); Auto swings at actors named by a WHEN 10 rule within reach (front first, then behind - the player turns). The reach box runs from the player's middle to its edge + reach, and from reach above its head to its feet. With tools, the other tools' fire-alone animation is Fire + the way it faces (entry 12 is the weapon's swing). Fire with no direction (anim entry 12) turns round with `v_face` like Idle (writers flip it when Flip is on).
- Synth filter (`filt` 1-15 two-pole low-pass, `fspeed` LFO in 0.25 Hz steps, `fdepth` up to +-3 octaves; output normalised to peak 0.9): `sfx_render` = `adf_reference.render_sfx`; a sound with a filter sweep may last 3 s (`sfx_max_seconds`), else 1.5 s. Dig Deep: filtered wind on sound 1, the bell on its post (actor 6, the miner's sprite pair, swinging Idle) chimes sounds 2 and 7 via WHEN 9 only while on screen, sword (Auto, reach 20) strikes baddies: +25, Thwack (sound 5), home; no hold-fire ladder rules.
- Disk 2 (version 12, `H_DISK2` 108, `D2_*`): the songs levels start with that no DO 18 rule plays (`disk2_song_flags`) go on `<disk>_disk2.adf` when the Build page's 'Level music on a second disk' is on (`proj.disk2_music`) or the game does not fit on one disk (build_adf retries with `adam_data_block(_p, false, true)`). Disk 2: first sector 'ADM2' + D2_ID (`disk2_id_add` = adf_reference `disk2_id_add`), songs from track 1, each on a track start; their music table offset has bit 31 set. The data block's D2 block = D2_ID, D2_RAW / D2_BUF: cleared memory after the data (raw track buffer 12800 bytes, then the biggest disk 2 song in whole tracks). Engine: its own floppy loader (the OS is gone) - `drive_on` / `drive_off` / `seek` (CIA-B PRB, /TK0 recalibration) / `raw_read` (disk DMA from the $4489 sync, 6400 words) / `decode_track` (AmigaDOS MFM, data checksums) / `track_read` (3 tries); `level_disk2` at the level card calls `song_fetch`, which finds disk 2 (`disk2_find`: last drive, DF1, DF0; 'PLEASE INSERT DISK 2' until it is in), says 'LOADING', reads the song into D2_BUF (`v_d2song` caches one) and shows 'DISK 2 ERROR - PRESS FIRE' if a track will not read. `music_play` plays a disk 2 song from D2_BUF. FS-UAE gets disk 2 in DF1 (`fsuae_disk2_arg`, Mac config `floppy_drive_1`). adf_reference: `proj['d2songs']` (MOD bytes in `songs`), `proj['_disk2']`; gen_examples writes `<name>_disk2.adf` when an example has `disk2_music`.
- Rule groups (`scr_ws_logic`): `parent` makes groups nest (tree order = run order, `group_order`, `logic_sort_rules`); a group switched off switches off the groups inside it (`group_off_in`, also used by the disk writer). Groups start folded (`group_new`, `groups_fold_all` when a project or example is opened).

### Hardware limits ADAM respects
- 8 hardware sprites (16 x 24, 3 colours), 4 colour pairs; actors with matching colours are paired automatically (`actors_alloc_channels`).
- Backdrop 320 x 256: up to 16 colours on A500/600 (sprites use colours 17-31), up to 128 on A1200 (sprites moved to 240-255 via BPLCON4).
- 4 Paula channels, driven by ptplayer (`datafiles/engine/ptplayer`, public domain) from CIA-B level-6 interrupts; the engine runs in supervisor mode. With no music, sound n plays on channel n & 3; while a song plays ptplayer picks the least disruptive channel.

### vasm pitfalls seen so far
- Local labels (`.x`) are scoped to the last global label — don't reuse names in one routine.
- `-no-opt`: short branches out of range are errors — widen to `bra`/`beq` (word). A `bra.s` to the very next instruction is invalid.
- `touch` is a mnemonic; avoid as a label.
