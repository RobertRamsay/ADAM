# ADAM — Claude Code guide

ADAM ("Amiga Dev and Art Machine") is a no-code Amiga game maker written in GameMaker (GML), by Bob / Polytricity Ltd. It is modelled on Bob's C64 No-Code tool (github.com/RobertRamsay/C64_NOCODE) and is a separate product from the older AMIGA_DEV_MACHINE_Git node editor.

Users paint a backdrop, draw sprites, place actors, write WHEN/DO rules, make sounds and levels, then ADAM writes a **bootable .ADF** for a stock **Amiga 500/600 (OCS/ECS, 1MB chip, FS-UAE model A600)** or **Amiga 1200 (AGA, 2MB chip)**, picked at launch.

## Golden rules (Bob's conventions — always follow)

- **Initialise every instance variable in `obj_app` Create** (arrays, structs, flags). Never rely on `variable_struct_exists` / `variable_instance_exists` checks. For data read from JSON, use `struct[$ "key"]` and `is_undefined` / `is_array` / `is_string`.
- **No ternary / shorthand if** (`a ? b : c`). Always full `if { } else { }`.
- **Never write hex as `$ff` at the start of an array literal** — `[$ff...]` parses as a struct accessor. Use `0xff` everywhere.
- **Never name a local `x` or `y`** (built-in instance variables). Use `_px`, `_iy`, etc.
- Brace style: Allman, 4-space indent, `_underscore` locals, as in the existing scripts.
- Bob reviews changes as diffs/patches. Keep changes focused, one feature per commit, with a clear message. If you hand him something to paste instead, use **FIND:** / **REPLACE with:** blocks.
- **No border / background / screen flashing in any of our games** (Bob). Only the ship / player itself blinks (DO 3).
- Accept a little frame lag in busy scenes (Bob); don't chase it endlessly.
- `#macro ADAM_DEV_TOOLS true` (scr_adf) enables the FS-UAE test-copy download. It must be `false` for public itch.io builds.

## How to build and check

- **Compile GameMaker from the command line** with Igor so compile errors can be read and fixed. Locate the runtime (usually `%ProgramData%\GameMakerStudio2\Cache\runtimes\runtime-*\bin\igor\windows\x64\Igor.exe`) and run a Windows VM build of `ADAM.yyp`. Iterate until **zero errors**; also clear Feather errors where possible.
- **Engine:** `powershell -File tools\assemble_engine.ps1` (needs vasmm68k_mot.exe).
- **Engine test without GameMaker:** `python tools\reference\gen_examples.py` then `powershell -File tools\run_adf.ps1 -Adf tools\reference\out\gem_hunter.adf` (or `-Model A1200`).
- `gen_examples.py` is deterministic: running it must not change `datafiles/examples/*.adam` unless the examples were meant to change. It also writes `datafiles/examples/shots/<name>.png` (`shot()`, 320 x 256 first screen) for the Home page's Example games list (`home_shot`); new files must be added to `ADAM.yyp`'s included files.
- Example sprite art: `tools/reference/arcade.py` holds the hand-drawn 'arcade' casts (Deep Dive, Firefly Night, Torchlight's hero, Dig Deep's bat / mole are there or in `ex_dig_deep.py`; the Miner is built from parts in `miner_rows`; the Gem Hunter / Piston Pass hero in `gh_art.hero`). Style: a dark outline in the darkest of the 3 colours, light from the upper left, front-on creatures drawn as a left half and mirrored (`sym`). Changing a sprite's colours is safe only where no other actor shares that set (pairs are matched by colours). The editor's look (gunmetal and silver) is `global.TH` in scr_theme plus `ui_panel` / `ui_inset` / `ui_rrect_rim` / `ui_grain` (scr_ui_draw) and `ui_button` / `ui_tab` (scr_ui_widgets).
- Release: Bob builds `_LITE` and `_PRO` zips himself (docs/RELEASE.md); no licence keys. Mac version lives on the `mac` branch.
- `docs/MAINTAINING.md`: troubleshooting guide (data flow, where things live, symptom -> code table). `python tools\check_comments_only.py [commit]` proves a change only touched comments (GML, 68000, Python).
- Bob does the hands-on UI checks in the running app; describe exactly what to click to verify each change.
- Each task ends with: clean compile, engine reassembled if touched, reference builder updated if the layout changed, examples regenerated if needed, and a short "how to verify" note.

## Architecture

### Editor (GameMaker)
One object, `obj_app`, draws everything in **Draw GUI** with an immediate-mode UI (`scr_ui_widgets`, `scr_ui_draw`, `scr_ui_help`). Every control registers a rect (`ui_register`) for hover help and tutorials. Pages (`WS_*` in `scr_ws_shell`): Home, Backdrop, Levels, Sprites, Animate, Tiles, UI, Actors, Logic, Sound, Music, Build.

| Script | Role |
|---|---|
| `scr_project` | Data model (`project_new`, `project_from_loaded` = loader + validator), per-page undo (`undo_keys`, `undo_mark`, `undo_mark_full`), settings ini. |
| `scr_machine` | Machine profiles (`machine_cur()`), launch picker, boing ball. |
| `scr_gfx` | Backdrop index surface + `sh_palette` shader (palette & copper-sky preview), sprite caches, font, PNG import (median cut). Painting writes `bd_buf` then uploads — never draws into the surface. IFF pictures (`iff_read`: FORM ILBM / PBM, ByteRun1, mask plane or transparent colour, EHB, 4-bit CMAPs; HAM / 24-bit refused; `iff_to_png` for the other importers). Indexed pictures (`indexed_read` by file contents: IFF, PNG colour type 3 / grey up to 8 bits with tRNS, not interlaced (`png_read_indexed`, `buffer_decompress` + unfilter), BMP 1 / 4 / 8 bits plain or RLE (`bmp_read_indexed`), GIF first frame (`gif_read_indexed`, `gif_lzw`); `indexed = false` = true-colour, import as RGB); `backdrop_import_indexed` keeps their own palette and pixels when they use up to `pal_count()` colours (used numbers packed down) and are up to 384 x 300 (cut round the middle). |
| `scr_ws_sprites` import | Sprites page 'Import picture or sheet...' (`spr_import_open` / `spr_import_load` / `spr_import_draw` / `spr_import_run`, state `spr_imp_*` in obj_app Create): PNG / JPG / GIF / BMP / IFF; cell size, margin, spacing, how many, see-through (alpha, or also the top-left colour), one set of 3 colours for all or each its own (median cut), or for an indexed picture its own colour numbers (`spr_imp_ix` / `spr_imp_ipal`, `spr_import_ixmap`: numbers in one group of 4 after its first - 17-19 as Amiga sprite colours - keep pen = number mod 4, else up to 3 numbers in order; a cell with more falls back to median cut), empty cells left out; fills slots from `spr_sel`, size = the smallest allowed that holds a cell (`spr_import_size`, edition limits). Editor only. |
| `scr_levels` | Levels page, terrain generator (`terrain_generate`, LCG — must match `gen_examples.py`), title/goal settings. |
| `scr_adf` | **Game data block + ADF writer**, FS-UAE launch/test-copy download. |
| `scr_sfx` | Synth + WAV sample import, crunch (rate/bits), preview (exact Paula output). |
| `scr_patch` | Patch sounds (sound `kind` 2, settings in `sfx.patch`, `global.PATCH_DEF` / `PATCH_PRESETS`): 3 oscillators, SVF filter + envelope, amp / pitch envelopes, 2 LFOs, 3 mod slots, chorus / drive / crush / echo, one-shot or looped. `patch_render` makes one sample at the Paula rate of the tracker note with the patch note's pitch class (`patch_root`). GML only (not in `adf_reference.py`); disk format unchanged. |
| `scr_ws_*` | One script per page. `scr_ws_logic` also owns rule groups. |
| `scr_examples`, `scr_tutorial` | Example loader, tutorials. (No in-app intro; the YouTube intro is rendered by `tools/intro`.) |
| `scr_report`, `scr_webhook_secret` | 'Submit your game' and crash reports, as in Amiga Dev Machine: both post a text message to one Discord webhook (`report_post`, answer in `report_async` from Async HTTP), only when the user clicks Send. Home > Community > 'Submit your game' (`home_submit`, `submit_open` / `submit_draw`, `submit_*` in obj_app Create): title, made by, link to the .adam project, contact, note, and an 'I understand' switch (the whole project will be open to everyone); one a minute; only the typed lines are sent. Crashes: `crash_init` (Create, after `settings_load`; not on `-adam_` dev command lines) installs `exception_unhandled_handler`, which writes `adam_crash_report.txt` in the save area; the next start asks before the machine picker (`crash_draw`; error, version, edition, platform, machine, page, actor / rule counts - nothing else), 'Ask me after a crash' = `[ui] crash_ask`. **`ADAM_WEBHOOK_URL` is committed empty** (public repo): the real URL is only in Bob's working copy, hidden with `git update-index --skip-worktree`; an `adam_webhook.txt` beside the exe overrides it; empty = nothing is sent and no question is asked. `report_selftest` (dev) checks the texts. |

Project data (`proj`) is plain JSON-able structs/arrays; `.adam` files are `json_stringify(proj)`.

### Runtime (68000)
`datafiles/engine/engine.s` is a **fixed, position-independent** engine (`vasm -pic`). ADAM never generates code: it appends a **data block** right after `engine.bin`; `boot.s` (bootblock) AllocMem's chip RAM, reads engine+data with trackdisk (copper loading bar) and jumps in.

Loading screen (ADAM Pro; `scr_loadscr`, `proj.loadscr`, `loadscr.s`): disk is `[boot][loading-screen block][engine][data]`; the bootblock's last 16 bytes are `screenload, screenmem, loadsize, bsssize` (0, 0 = plain bar). Block = `loadscr.bin` + `LS_*` header (48 bytes, version 2: `LS_MODE` fill direction 0 L→R / 1 R→L / 2 bottom→top / 3 top→bottom; `LS_NPIC` / `LS_PICS` pictures at a percentage, `PI_*` 16 bytes) + ADAM's copper list (BPLxPT / SPRxPT are offsets from the block, fixed up by init) + picture planes + a strip of the full bar; entries 0 init / 4 progress (d0.w 0..1024) / 8 done; freed before the engine starts, falls back to the plain bar without the memory. Editor: UI page Loading screen tab (`ui_page_tab` 1, `loadscr_page_draw`; Pro only) — backdrop or own PNG (`picture_quantize`, 1-5 planes, A1200 up to 8), `ls_mode`, `proj.loadscr.pics` { spr, x, y, pct } (up to `LS_PIC_MAX` 16), bar place / size, HUD frame style or Custom pieces (or PNG strip, `loadscr_import_strip`), progress slider / Play preview (`loadscr_preview_update`). In adf_reference.py: `ls_new`, `loadscr_block`, `adf(..., ls)`. Dig Deep (Pro) has a stone bar and cast turning up at 20 / 45 / 70 / 90 %, Lesson 7.

Registers held: `a4` = data block, `a5` = V+128 (variables; per-actor state is a 128-byte record per actor (`ACTV_SIZE`), `v_xx(a5,Dn)` with Dn = actor << ACTV_SHIFT, up to MAX_ACT = 32), `a6` = $dff000.

**Data block header** (offsets from data start; longs are offsets, 0 = absent):
`0 'ADAM' | 4 version | 6 flags (bit0 AGA; test copies: bit1 lives never run out, bit2 F8 skips the level, high byte = level to start on) | 8 depth | 10 nact | 12 nrule | 14 lives | 16 show score | 18 show lives | 20 hud row | 22 hud colour | 24 msg colour | 26 player actor (-1) | 28 game block | 32 palette | 36 planes (original) | 40 actors | 44 rules | 48 sfx table | 52 game-over text | 56 win text | 60 sprite pair colours | 64 display planes | 68 copper sky (256 x $0RGB; AGA: + 256 words of low nibbles, written with LOCT) | 72 painted ground (320 words) | 76 work planes (backdrop + hills) | 80 music table | 84 second display (BOBs) | 88 BOB background | 92 tile world | 96 custom HUD | 100 scroll block | 104 named palettes | 108 disk 2 | 112 items | 116 logic` — header 120 bytes, version 19 (19 = DO 41..43, IF counter lines, WHEN 1 once a press - no header field; 18 = logic block `H_LOGIC`: `LG_HEALTH`, `LG_TIME` 10 words; 17 = level maps on disk 2, `D2_MAP`; 16 = a tile map per level; 15 = animated tiles; 14 = BOB frame headers; 15 / 16 / 17 added no header field; the full list is beside `poke16(_b, 4, ...)` in scr_adf). Music table (`M_*`, docs/MUSIC_CONTRACT.md): nsongs word, 10 level-song bytes ($FF none), then { offset, length } of each ProTracker MOD.

- **Any layout change must be made in three places: `engine.s`, `scr_adf.gml`, `tools/reference/adf_reference.py`.**
- `V` lies more than 32 KB into engine.bin: reach it from `a5`, or `lea start(pc)` + `add.l`, never `lea V(pc)`.
- BOBs (Pro): actors with `A_BOB` are drawn by the blitter into a double-buffered display (`bob_draw` / `bob_flip`), wiped from the background buffer each frame; images are the sprite's size (16-64 wide in steps of 16, 16-64 high; `A_BSIZE` = BLTSIZE), a mask then depth planes, in the nearest backdrop colours. A sprite bigger than 16 x 24 is always a BOB. Lite puts 8 actors on the disk as sprites, Pro up to 32 (actors after the 8th sprite become BOBs). Each BOB frame starts with a 16-byte `BI_*` header (first drawn row, rows, first drawn word, words, rightmost pixel, planes empty / solid under the mask); `bob_draw` and its wipe blit only that part.
- Animations (version 5): `A_ANIM` (actor record offset 48) points at a table of 136-byte entries (`AN_*`, `ANIM_SIZE`; 16 frames since version 8): Idle, Walk, Jump, Fall — each { frames 1..16, rate, mode 0 loop / 1 once / 2 ping-pong, 0, 16 longs facing right (`AN_RIGHT` 8), 16 longs facing left (`AN_LEFT` 72) }. ADAM fills empty animations from the others (`anim_plan` in scr_project = `anim_plan` in adf_reference.py); the two-frame animation of older projects is written as a table too. `place_sprites` picks the animation (Jump / Fall only for roles 6-8 in the air) and frame from `v_anim - v_astart`; frame offset in `v_fofs`. `A_SPR2` is now only a hopper's crouch frame. With 8 directions (`anim_dirs`, `A_AMODE` bit 0) the table has 12 entries (4..11 = N NE E SE S SW W NW via `dir_tab`, last in `v_dir`); ADAM bakes turning round into them (`flip`, `DIR_CHAINS` / `anim_dir_chains`); an empty Idle is mode 3 = stand facing the last direction. Fire animations (`A_AMODE` bit 1, 21 entries: 12 Fire, 13..20 Fire + N..NW) play while fire is held; Animate page 'With Fire' layer.
- Hit / Die (`A_AMODE` bit 2; slots `ANIM_HIT` 21 / `ANIM_DIE` 22, `ANIM_COUNT` 23, `ANIM_FIRE_END` 21): two more entries after the 4 / 12 / 21 others (empty Hit plays Die or Idle, empty Die plays Hit; `anim_plan_k` maps slot to plan index). DO 26 sets `v_aplay`; `place_sprites` plays it once and holds the last frame, then `anim_ended` sets `v_aplay` -1, the actor's bit in `v_aended` and `v_aendk`; WHEN 16. Dig Deep: sword makes a slime safe and plays Die, WHEN Die ends sends it home. `hide_sprites` clears all 16 + 16 frame longs.
- Tile world (version 6, `H_TILES`, `scr_tiles` / `WS_TILES`): one tile size per game (`proj.tile_size` 8/16/32/64, `tile_geometry()`), up to 512 tile types (`TILE_MAX`; Lite 96) — `T_*` header 44 bytes (size, shift, line, ncol, nrow, ring), `TP_*` records 8 bytes (byte flags: bit0 solid, bit1 dig, bit2 goal, bit3 ladder, bit5 changed-anim; byte sound; words hard, points, becomes), 4-letter names; map up to 1024 x 1024 tiles (Lite 256 x 256), never over 32640 pixels (`WORLD_PX_MAX`); cells are bytes, or words with more than 256 tile types (`T_FLAGS` bit 1). The engine copies the map to BSS (cleared memory after the data; bootblock allocates `loadsize + bsssize`, poked into the last 8 bytes of boot.bin). The scrolling picture is a ring of `NROW x S x LINE` bytes per plane, kept twice: map pixel (x, y) lives at `(y x LINE + x / 8 + 2) mod RING` (`draw_cell`, `cam_window`, `cop_scroll`: BPLCON1 fine scroll, DDFSTRT $30, AGA FMODE 0), under a copper HUD split at line 8 with modulo LINE - 42; its size does not depend on the map. Actor coordinates are world pixels; collision with solid tiles (`box_solid`, `tile_hres` — steps up tiles up to 16 high — `tile_vres`, `tile_phys`). Dig and place (player only): fire + direction digs, fire alone places the carried tile, up jumps. Tile worlds use 7 actors, all hardware sprites (no BOBs): DDFSTRT $30 steals sprite 7's DMA, so pair 3 holds one actor (`ACT_MAX_TILE`). Editor draws the map through `tile_view_surface`; atlas holds 32 tiles a row. Example: Dig Deep (`ex_dig_deep.py`, 16 x 16, Pro extra). Ladder: a platform player on it climbs with up / down (no gravity), lines up with the tile column (`on_ladder`, `snap_col`).
- Multi-disk (Bob, Oct 2026): level music and level tile maps on disk 2 done — see Disk 2 and Level maps; per-level backdrops on disk 2 not done.
- Level maps (version 16 / 17, ADAM 1.3): a tile world can give each level its own map (`proj.level_maps`, Tiles page 'Map for' dropdown: Own map / Level 1's; `level_maps_new`, `level_map_own`, `level_maps_on`, `tmap`, `tmap_editable`, `maps_all`, `map_resized`). Disk: `T_FLAGS` bit 2 = `T_MAP` points at 10 longs, one map per level (`adf_map_cells`, `adf_level_maps_used`); engine `tiles_start` / `lmap_entry`. An entry with bit 31 set lives on disk 2 (after the songs, `adf_music_table(..., _d2maps)`): `D2_MAP` (D2 block offset 12) = the map buffer, `map_fetch` reads it at the level card. `build_adf` also moves maps to disk 2 when chip RAM is short. Levels page in a tile world: map info box (`lvl_openmap`), no hills (hill settings hidden), MAP / "= 1" badges.
- God mode and Test a level (1.3, Build / Levels pages; `god_on`, `god_flags`, `build_tflags`, `build_ws_build(_run, _start, _god)`): the test copy sets `H_FLAGS` bit 1 (lives never run out), bit 2 (F8 = $157 skips the level, `level_skip`) and the high byte (level to start on). Only test copies; Build ADF never sets them.
- Health and time limits (version 18, from the C64 tool): `proj.health` (Home page, 0 = none, up to `HEALTH_MAX` 99) and `proj.level_time` (Levels page, seconds per level, 0 = none, up to `TIME_LIMIT_MAX` 999; levels off = level 1's). Disk: logic block `H_LOGIC` 116, written only when one is set. Engine `health_fill` (game start, lost life), `time_reset` (level start, lost life), `time_tick` (once a second, `v_tleft`, `v_tout`), `level_tlimit`. Standard HUD: TIME nnn at column 13 and HEALTH nn at 22 (LIVES moves to 32) when there is no goal counter and no digging; else Build warns to use custom HUD fields 8 / 9.
- Moving platforms and patrol distance (1.3): actor `stand_on` (`A_CARRY` bit 1) = can be stood on — `plat_save` / `plat_stand` (after `phys_core`; a faller up to `PLAT_GRAB` 12 px below the top lands) / `plat_carry` move riders with it; the top is the first drawn row (`sprite_top`). `patrol` (`A_CARRY` low byte, x 8 px, up to `PATROL_MAX` 255) limits a patroller to that far from its start the way it starts moving (`pat_lim`; one placed outside turns round where it is). Actors page draws platform tops and the selected patroller's range (`act_patrol_range`). Diagonal patrol (`diagonal`, roles 2 / 3, `A_CARRY` bit 2 = `CARRY_DIAG`): `move_actors` `.diag` moves x as across (`pat_lim`, `v_dx`) and y by the same amount, down going right when `A_LEFT` = `A_UP`; a step off the top / bottom is not taken and it turns so y comes back in; tile worlds `tile_dres` (back in x and y, flip `v_dx`); editor `act_diag_ends`. Columns (version 19, actor `column`, Actors page 'Reaches the floor', `A_CARRY` bit 3 = `CARRY_COL`; not tile worlds / scrolling): always a BOB (`actors_bob_flags` / `bob_flags`); `bob_blit` (the one-BOB cut, shared by `bob_draw` and stamping) draws the frame's last row again down to line 255 (A / B modulo = minus the blit width) and returns the whole rectangle for the wipe. A stopped column (`v_still`) is stamped once into `v_back` and both displays (`col_state` / `col_stamp`, `v_stamp`, `v_stx` / `v_sty`) and skipped, so only moving columns cost blitter time (as Kalle Kloakk's pillars); `col_unstamp` copies the rectangle back from `v_work` (+ `draw_hud`) when it moves, hides or is moved; `init_actors` clears `v_stamp`. Sides are walls for a platform player (`col_walls` before `physics`, `v_colall`): walking or jumping across into one whose top is more than `PLAT_GRAB` above its feet puts it back at `v_ox`. Editor stage: `draw_sprite_column_cols`; gen_examples `shot()` draws it too. A column picture can be the whole pillar (Pro sprite heights 128 / 256, `spr_size_ok`, `lim_spr_h` 256): `bob_blit` cuts it off at the floor `v_colbot` (256, or the top of a HUD in the bottom half, set in `init_display`; editor `col_floor()`); writers give a column `A_YMAX` / y clamp of 256 - min(h, 32). Eased patrols (actor `ease`, roles 1-3 not diagonal, `A_CARRY` bit 4 = `CARRY_EASE`): `ease_step` gives full speed in the middle half of the way, slowing to a quarter pixel a frame at the ends (1/16 remainder in `v_xsub` / `v_ysub`). WHEN 23 'Fire pressed, stick held' (n = 0 up / 1 down / 2 left / 3 right, `global.STICK_NAMES`; `.firedir`, once a press). Example: Pillar Run (`ex_pillar.py`, PRIVATE - shipped only in 1.3.1, not since 1.3.2: `gen_examples.py pillar_run` writes it to `tools/reference/out/private` (`PRIVATE` set); a template with placeholder art at the game's sizes for Kalle Kloakk's authors to import their own): ten 32 x 256 columns edge to edge, eased, IF counter cards stop each and show the next; the last shows the hero (stopped at level start), door and pick-up (fallers, DO 4 home so they land on their columns); door needs IF counter 11 (the pick-up adds one); WHEN 23 down + fire = lose a life + DO 43; custom HUD one row at the bottom.
- Animated tiles (version 15, Pro only — `pro_gate("Animated tiles")`, `lite_trim` makes them still; docs/ISO_LAYERS_PLAN.md step 1): a tile's `anim` = 2..8 tile numbers shown in turn (`anim_rate` 50ths, `anim_mode` 0 loop / 1 ping-pong); map and physics keep the tile type. `T_ANIM` (tile block offset 44, `T_PROPS` moved to 48) → `TA_*`: count, `TA_PICS` (NT words tile → picture, engine writes into it), then `TR_*` records of 28 bytes (tile, rate, mode, frames, 8 pictures, runtime count / step / dir). `draw_cell` draws `TA_PICS[tile]`; `tile_anim` (main loop after `cam_window`) steps each, marks changed tiles with `TP_FLAGS` bit 5 and redraws their cells in view a few rows a frame (`v_tarow`, `TANIM_DRAW`); `tanim_reset` at level start. Up to `TILE_ANIM_MAX` 32. Writers: `tile_anims_on_disk` (scr_tiles) = `tile_anims` (adf_reference). Editor: tile panel Animation box (`tile_anim_pic`). Shoot 'em up maps do not animate them (Build warning). Dig Deep: water (4 frames) and torches.
- Actor record = 68 bytes (`A_*`; v9 added `A_PAT` 52, `A_ENTER` 54, `A_HP` 56, `A_RANK` 58; v10 `A_TYPE` 60, `A_FIRE` 62, `A_FRATE` 64, `A_FPAT` 66; `A_XMAX` / `A_YMAX` = 320 - width / 256 - height). Rule record = 16 bytes (`R_*`). Sfx entry = 8 bytes (offset, length in words, Paula period), one per sound (1..`SFX_MAX` 64, Lite plays `LITE_SOUNDS` 8; folders `proj.sound_groups`, `sfx.group`); only sounds a rule or dug tile plays get sample data (`sfx_used_on_disk`); engine masks the sound number with 63. Game block = `G_*` (levels, terrain colours, goal, title text, 320 heights per level).
- Roles: 0 player, 1 bouncer, 2 patrol L-R, 3 patrol U-D, 4 chaser, 5 still, 6 platform player, 7 hopper, 8 faller, 9 shot, 10 flyer, 11 option, 12 effect.
- WHEN: 0 touch, 1 fire, 2 every N s, 3 score reaches, 4 lives out, 5 game starts, 6 actor jumps, 7 level starts, 8 fire held with stick still N tenths (once per hold), 9 every N s while actor a is on screen (`on_screen`; out of view fires a second after coming back), 10 player's weapon strikes actor b (`v_struck`), 11 thrown or shot actor a hits actor b (b = a: anything; `v_hits`), 12 player picks actor a up (`v_picked`), 13 N s into the level (once, `v_ltime`), 14 fire held: at once, then every N frames, 15 shmup map reaches its top (once, `v_mend`), 16 actor a's Hit / Die animation ends (n 0 Hit / 1 Die / 2 either), 17 player gets item n (`v_igotp`, a frame late), 18 player uses item n (space bar menu, `v_useit`) while touching actor b, 19 actor a reaches edge n (0 left, 1 right, 2 top, 3 bottom; `edge_test`), 20 actor a hits the scenery (solid tile beside it, else hills / painted ground under it; `scen_test`), 21 the counter reaches n (then back to 0), 22 the level's time runs out (`v_tout`). 19 / 20 use `copy_find` (the actor or a copy, shown, on this level) and the touch latch.

### Hardware limits ADAM respects
- 8 hardware sprites (16 x 24, 3 colours), 4 colour pairs; actors with matching colours are paired automatically (`actors_alloc_channels`).
- Backdrop 320 x 256: up to 16 colours on A500/600 (sprites use 17-31), up to 128 on A1200 (sprites at 240-255 via BPLCON4).
- 4 Paula channels, driven by ptplayer (`datafiles/engine/ptplayer`, public domain) from CIA-B level-6 interrupts; engine runs in supervisor mode. With no music, sound n plays on channel n & 3; while a song plays ptplayer picks the least disruptive channel.

### vasm pitfalls
- Local labels (`.x`) are scoped to the last global label — don't reuse names in one routine.
- `-no-opt`: out-of-range short branches are errors — widen to `bra`/`beq` (word). A `bra.s` to the very next instruction is invalid.
- `touch` is a mnemonic; avoid as a label.

## Product: ADAM Lite (free) and ADAM Pro (paid)

- **Decision (Bob, Oct 2026): Lite and Pro have the same features; Pro raises ceilings and adds extra example games and lessons.** Never cripple Lite. `pro_on()` / `feature_gate()` are always true; `pro_edition()` / `pro_gate("Feature")` gate the Pro extras (`pro : true` in `global.EXAMPLES` / `les_defs`; Lite shows them with a Pro label, locked with a short "Pro" note rather than hidden).
